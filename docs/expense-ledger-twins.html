Two mainstream stacks

Python with Flask and Node.js with Express are the two most common small-server stacks, so either build is easy to host and to hand to any developer.

Pages built on the server

Every screen is plain HTML from the server, so the two builds can be compared byte for byte. There is no front-end build step and no JavaScript to install.

One command each

One command runs a build and one tests it. There is no database server: the data is one JSON file in the same format for both, so a file written by one build can be opened by the other.

Requirements 1/2 · FR-01–09

Functional requirements

Short and plain. Each requirement is tagged in the code of both builds (search for its ID) and proved by tests in both suites.

FR-01

Shared layout and navigation

all screens
  • Every screen has the same sidebar with five links: Overview, Expenses, Add expense, Reports and Data.
  • The link for the current screen is highlighted and carries aria-current="page".
  • The browser tab title reads "<Screen> · Expense Ledger". The footer reads "Expense Ledger 1.0.0 · Amounts in Omani rial (OMR)".
FR-02

Monthly headline figures

GET /, GET /?month=YYYY-MM
  • Shows four figures for the selected month: total spent, number of expenses, daily average and largest expense.
  • The total also shows the change against the previous month as a percentage. If the previous month has no spending, it says "No spending in <Month>".
  • Daily average = total ÷ days in the month. For the current month, total ÷ days elapsed so far.
  • With no month in the URL, the month of the most recent expense is shown, or the current month if there are no expenses. Previous/next links move one month.
FR-03

Spending by category

GET /
  • One row per category with spending in the month: name, bar, amount and share of the month (one decimal).
  • Rows are sorted by amount, highest first. Equal amounts keep the fixed category order.
  • A composition strip above the rows shows the same shares in the fixed category order.
FR-04

Spending-through-the-month chart

GET /
  • A step chart of the running total by day for the selected month, with the previous month drawn as a dashed reference line.
  • The y-axis uses round gridlines (1, 2 or 5 × 10ⁿ OMR, at most 5 lines).
  • Hovering a day shows its date, that day's spending and the running total (native SVG tooltip, no JavaScript).
FR-05

Latest expenses

GET /
  • Lists the five most recent expenses of the month (newest date first, then newest entry), with a link to the full filtered list.
  • A month without expenses shows "No expenses in <Month Year>." and an Add expense button.
FR-06

Expense list

GET /expenses
  • A table with date, description (notes underneath), category, amount, and Edit / Delete actions.
  • Above the table: the number of rows shown and their total, e.g. "36 expenses · OMR 1,540.800", plus the active sort order.
  • After an add, edit or delete, a confirmation notice is shown (see Messages).
FR-07

Filter and search

GET /expenses?month=&category=&q=
  • Filter by month (All months or one month that has data), by category (All categories or one), and by free text.
  • The text search ignores case and matches the description or the notes. All filters are combined (AND).
  • The filter state lives in the URL, so every filtered view can be bookmarked. Reset clears all filters.
  • With no matches: "No expenses match these filters." With no data at all: "No expenses yet."
FR-08

Sorting

GET /expenses?sort=
  • Sort options: Newest first (default), Oldest first, Amount: high to low, Amount: low to high.
  • Ties break by entry number: newest entry first for descending sorts, oldest first for ascending sorts.
FR-09

Add an expense

GET /expenses/new, POST /expenses
  • Fields, in screen order: date (defaults to today), amount, description, category and optional notes.
  • A valid form is saved and the app goes to the list (HTTP 303) with the notice "Expense added."

Requirements 2/2 · FR-10–18

Functional requirements (continued)

FR-10

Validation with exact messages

POST /expenses, POST /expenses/<id>
  • Every field is checked on the server, rules in the order listed under Messages. Each field shows at most one message; the summary lists them in screen order.
  • An invalid form comes back with HTTP 422, the values entered, a summary box linking to each field, and the message under each field.
  • Amounts accept digits with up to three decimals; thousands commas are ignored. More than three decimals is rejected, never rounded.
FR-11

Edit an expense

GET /expenses/<id>/edit, POST /expenses/<id>
  • The form opens with the saved values, uses the same validation, and saves with the notice "Expense updated."
  • An unknown or malformed id shows the 404 page.
FR-12

Delete with confirmation

GET /expenses/<id>/delete, POST /expenses/<id>/delete
  • A confirmation screen shows the expense and warns that this cannot be undone. Cancel returns to the list.
  • Confirming deletes the expense and returns to the list with the notice "Expense deleted." Entry numbers are never reused.
FR-13

Monthly report

GET /reports?month=YYYY-MM
  • All eight categories with this month, previous month, change in OMR, change in % and share of the month, plus a Total row.
  • Change % shows "—" when the previous month is zero. Previous/next links move one month; the default month follows FR-02.
FR-14

CSV export

GET /export/expenses.csv, GET /export/report.csv?month=
  • The list export uses the current filters and sort. The report export holds the monthly report.
  • Files are UTF-8 with a byte-order mark (Arabic text opens correctly in Excel) and CRLF line endings, and use RFC 4180 quoting.
  • Text cells that start with = + - @ get a leading apostrophe (formula-injection guard). Amounts are plain numbers with three decimals.
  • File names: expenses-all.csv or expenses-YYYY-MM.csv, and report-YYYY-MM.csv.
FR-15

Read-only JSON API

GET /api/expenses, GET /api/summary?month=
  • /api/expenses takes the same filters and sort as the list. /api/summary returns the overview figures for a month.
  • Responses are compact UTF-8 JSON with stable key order, and give each amount as a string ("18.450") and as an integer in baisa.
FR-16

Data tools

GET /data, POST /data/reset …
  • Shows how many expenses are stored, the date range they cover and where the data file is.
  • Restore sample data and Delete all expenses each need a confirmation tick. Without it the page comes back with HTTP 422 and "Tick the box to confirm."
FR-17

Storage and money rules

data/ledger.json
  • Data lives in one JSON file. On first run it is created from seed.json, and every save is atomic (temporary file, then rename).
  • Amounts are stored as whole baisa (1 OMR = 1000 baisa) and never as floating point. They display as OMR 1,234.500.
  • Averages and percentages round half away from zero, using integer arithmetic only.
  • Dates are ISO 8601 (YYYY-MM-DD) and show as "24 Nov 2026".
FR-18

Errors, status codes and redirects

any unknown URL
  • Unknown pages return the 404 page. A wrong method on a known URL returns the 405 page. Routes are case-sensitive and have no trailing slash.
  • Every successful POST redirects with 303 See Other and an empty body, so a refresh never resubmits a form.

Walkthrough and handover

What to click, and what you should see

Walk both builds side by side: :5001 and :5002
  1. Overview

    November 2026: OMR 496.850 spent, 13 expenses, down 6.5% on October. The arrows change the month; August 2026 is empty.

  2. Expenses

    Filter November + Utilities (3 expenses, OMR 45.450), search “grocer”, try the four sort orders, export the CSV.

  3. Add expense

    Submit the empty form: four messages at once, HTTP 422. Then add a valid expense: “Expense added.”

  4. Edit

    Open entry #30, change the amount, save: “Expense updated.” The total moves by the difference.

  5. Delete

    Confirmation page, then “Expense deleted.” The next new expense gets a new number; #36 is never reused.

  6. Reports

    Every category against October, with the change in OMR and %, and the share of the month. Export the CSV.

  7. Data

    “Delete all expenses” without the tick shows “Tick the box to confirm.” Restore the sample data afterwards.

In the handover

  • twin-a-flask/ and twin-b-express/, each self-contained with its README, tests and sample data
  • docs/REQUIREMENTS.md: requirements, every message and the traceability matrix
  • spec/: requirements, scenarios and sample data as JSON, the shared source of truth
  • tools/: parity check, screenshots, traceability, sync
  • this document as PDF, with ZIP files attached: each build on its own, and the whole delivery (open the PDF in Acrobat or Firefox to see the attachments)

Changes are part of the job

Want a different app, a third stack (Django, Laravel, .NET, React Native) or more features? Each change is made in both builds and added to the spec, the scenarios and the parity check, so the twins stay identical.

The full source is in the repository linked in the entry description, ready to clone.
